# Теги видимости: наследуемая таксономия групп объектов (фаза 1)

**Статус: заморожен.** Записано и заморожен: 2026-09-10. Сложность: L.
Предшественник — [../editor-peek-visibility.md](../editor-peek-visibility.md) (фаза 0, Peek: пер-юзерская
несериализуемая маска над автовыведенными ветками дерева). Фаза 1 добавляет **самостоятельную сущность** —
именованный тег, живущий в файле сцены, со своим отгружаемым состоянием и рантайм-API.

## Почему заморожен

Разбор прошлого опыта (см. ниже) даёт один одинаковый вывод у всех движков: **эта фича окупается на
масштабе**. «Сотни узлов в сцене» (Godot proposal #7451), открытые миры (Unreal Data Layers), большие
уровни («чем шире используете слои, тем легче — начинайте с самого начала», доки Unreal). У playable-ad
несколько десятков узлов (самая большая наша сэмпл-сцена — 40) и 3–5 очевидных групп (фон, геймплей, HUD,
эндкард), **которые уже являются родительскими узлами**. Плюс наш собственный репозиторий уже выбрал другое
решение той же проблемы: коммит `20c32d88` вынес UI-оверлеи из `main.pix3scene` в `scenes/ui/result.pix3scene`
по четырём рецептам, и в роутере `CLAUDE.md` на это есть отдельная строка про `scenes/ui/`.

Постоянная цена, которую платим сразу и навсегда: пятая сущность в одном смысловом поле (`groups`,
`visible`/`initiallyVisible`, `editorOnly`, `CanvasLayer2D`, фильтры 2D/3D) + расход промпт-бюджета агента на
каждом ходу + новое поле в формате сцены с обратной совместимостью. Разовая — ещё **+700–900 строк** поверх фазы 0.

## Критерии разморозки (проверяемые, любой из трёх)

1. **Кросс-корневой кейс подтверждён на практике.** В реальном проекте понадобилась группа, которая
   физически не может быть поддеревом, потому что иерархия Pix3 расщеплена по технологии рендера:
   «Tutorial» = рука-спрайт в HUD + подсветка в 3D-мире + стрелка; «Debug» = коллайдеры + гизмо + FPS-лейбл.
   Это единственный аргумент за фичу, которого не закрывает ни дерево, ни фаза 0.
2. **Веток стало больше, чем помещается.** В типовой сцене регулярно >8 верхнеуровневых ветвей, то есть
   стрип фазы 0 уходит в оверфлоу и автовывод перестаёт быть удобным.
3. **Агент упирается.** В логах Flow регулярно видно, как агент гоняет `set_property visible` по узлам
   пачками вместо одного вызова, или просит несуществующую ручку «скрыть всё, кроме X» в игре
   (не в редакторе — редакторский случай закрыт `peek`).

Если ни один критерий не выполняется — плана не размораживать: фаза 0 закрывает всё, что подтверждено.

## Дизайн (готов к исполнению)

### Понятие и имя

**Tags** — одиночное членство, **наследование по поддереву**, ноль связи с порядком отрисовки.

Имя «слои» отвергнуто сознательно. Во всех инструментах, где «слой» — строка вертикального списка
(Photoshop, Illustrator, After Effects, Figma, Sketch, панель выделения PowerPoint), строка **одновременно
задаёт z-порядок**. Плоский тег поперёк структуры без порядка есть ровно у двоих — слои AutoCAD и
коллекции Blender — и оба учатся только по туториалу. Готовые грабли рядом: Unity `Layer` против
`Sorting Layer` («сменил Layer — порядок спрайта не поменялся» — топовый вопрос новичков 2D). Чипы — это и
есть общепринятый UI тегов, и в чате фраза «скрой всё с тегом Tutorial» звучит естественно.

Тултип, снимающий главное недопонимание: «Теги группируют объекты, чтобы показывать и скрывать их вместе.
Порядок отрисовки они не меняют — за это отвечает дерево сцены».

Ранжирование альтернатив: Tags > Sets > Collections > Views > Layers > Groups > Screens. `Groups` занято
дважды (узлы `Group2D`/`Group3D` и Groups Engine), `Screens`/`Scenes` коллидируют с файлами сцен и
конвенцией `scenes/ui/`.

### Почему одиночное членство и наследование

Доказательства однонаправленные:

- В Godot есть мульти-членские `groups`, и для «скрыть весь HUD» их **не используют** — там нет семантики
  видимости; форумный идиом — скрипт `for node in get_nodes_in_group("debug"): node.hide()`, а proposal
  #7451 просит дать редактору оверрайд видимости **поверх** групп (открыт с 2023, не реализован).
- В Unity мульти-целевые `Tag` для видимости не используют никогда, используют одиночный `Layer`.
- Единственный движок, сделавший группы видимости мульти-членскими — Unreal (панель Layers), и это ровно
  тот, который заброшен.
- Construct 3 / GameMaker: одиночное членство (объект лежит на одном слое комнаты/лэйаута) — и им
  пользуются каждый день.

**Наследование по поддереву не делает никто**: Unity спрашивает «применить к детям?», в Godot предложение
наследовать `visibility_layer` закрыто (пользователю в #10014 пришлось руками проставлять слой каждому
потомку и каждому canvas-item), в Cocos дети всегда `DEFAULT` независимо от родителя. Это наш настоящий
дифференциатор, а не сам чип-стрип: пометил корень экрана — весь экран помечен.

Правило: **эффективный тег** = свой тег → ближайший помеченный предок → `default`. Каскад видимости —
родной three.js, тот же, что у `visible`.

### Где живёт правда

**Тег — schema-свойство `properties.tag`**, а не top-level ключ вроде `groups:`. Причины:
`SceneSaver.serializeNodeProperties` копирует `node.properties` целиком (round-trip даром); **оверрайды
префаб-инстансов диффятся только по `properties`**, значит top-level ключ переопределить в инстансе
нельзя; `set_property`, `UpdateObjectPropertyOperation`, инспектор и undo работают сразу.

**Таблица — `metadata.tags`** документа: метаданные уже round-trip'ятся (`SceneLoader` → `SceneSaver`) и уже
зеркалятся в `appState.scenes.hierarchies[id].metadata`, то есть UI подписывается через Valtio без новой
ветки состояния, а старый редактор её не теряет. Таблица **опциональна**: список тегов = таблица ∪ фактические
теги ∪ `default`; она добавляет только порядок, цвет и стартовое состояние.

```yaml
version: 1.0
metadata:
  tags:
    - { name: world, color: '#5ac8fa' }
    - { name: hud,   color: '#ffcf33' }
    - { name: menu,  color: '#ff6b6b', startsHidden: true }   # единственный способ уехать скрытым в билд
root:
  - id: hud_root
    type: CanvasLayer2D
    properties: { tag: hud }
    children:
      - id: minimap
        properties: { tag: debug }        # свой тег перебивает наследованный
```

**Только имена, никогда индексы битов.** Unity/Cocos на индексах ловят коллизии при импорте пакетов
(`TagManager` не едет вместе с префабами) и канонический баг `layerMask = 8` вместо `1 << 8`; Godot на
голых строках получил «very error prone since I'm just using strings everywhere» (#3789) и в 4.x добавил
Global Groups; Unreal в 5.1 разнёс Data Layers на проектные **Assets** и мировые **Instances** именно
чтобы идентичность слоя выживала переименование и переиспользование между уровнями. Отсюда же вопрос,
который решать при разморозке: держать таблицу пер-сцена (как здесь) или завести проектную палитру имён и
цветов, а в сцене оставить только оверрайды и `startsHidden`. Аргумент за палитру: в Flow агент плодит
`scenes/ui/*`, и `hud` в каждой сцене будет своего цвета и порядка.

### Два канала видимости

| | Peek (фаза 0) | Игровое состояние (фаза 1) |
| --- | --- | --- |
| Где | localStorage по пути сцены, пер-юзерски | `metadata.tags[].startsHidden` + рантайм `scene.tags.*` |
| Сериализуется | никогда | да / рантайм |
| Undo | нет (операция без `commit`) | правки таблицы — да |
| Кто скрыл | «я, чтобы посмотреть» | «игра, по правилам» |

Разделение подтверждено и наличием, и отсутствием: Unity Scene Visibility (только Scene view, состояние в
`Library/`, «безопаснее деактивации объектов») и Unreal Data Layers (`InitialRuntimeState` отдельно от
пер-юзерского «загружен/виден») — работает; Godot (глазик = сериализованный `visible`, #12453 с 2017 →
#3433, 78 реакций), GameMaker и Construct («глазик = стартовое состояние в игре») — десятилетие тикетов
«скрыл при авторинге, так и ушло в игру». **Unity прав в хранении, Unreal Data Layers — в семантике,
наследования нет ни у кого.**

**UI-правило, добытое из провала Blender:** на чипе **одно** состояние — авторский глаз. `startsHidden`
живёт в редакторе тега со своей иконкой, максимум пассивный бейдж на чипе. Хорошая модель — колонка **Plot**
в AutoCAD: своя иконка (принтер), своя колонка, состояние «видно, но не напечатается» понятно с первого
взгляда. Плохая — Blender: монитор и камера рядом, похожие, и по умолчанию скрыты фильтром аутлайнера
(у них по этому свой внутренний таск про юзабилити переключателей #61361).

### Рантайм-API

```ts
scene.tags.hide(name) | show(name) | toggle(name) | isHidden(name) | list() | nodesIn(name) | onChanged(cb)
node.tag: string | undefined      // свой тег, реактивный
node.effectiveTag: string         // с учётом предков, 'default' если нет
```

Godot-подобный минимум. **`hide` — это сахар над `visible` участников (корней тега), а не третье состояние
видимости**: третье состояние — это Blender с пятью переключателями и репутацией «почему объект есть во
вьюпорте и нет в рендере». Скрытие тега **не останавливает `onUpdate`** (тот же контракт, что у `visible`),
но останавливает ввод через `isVisibleInTree()`. `groups`/`callGroup` не трогаем: они про логику.

### Агент

Инструмент **`tags`**: `{ action, name?, color?, nodeIds?, startsHidden?, order? }`, действия
`list/create/rename/recolor/reorder/delete/assign/set_starts_hidden` плюс игровые `hide/show` — и **все
редакторские действия остаются в инструменте `peek` из фазы 0**, чтобы канал был виден в имени вызова.
`find_nodes` получает фильтр `tag`, `create_node` — необязательный `tag`, `scene_tree`/`node_inspect` —
поля `tag`, `effectiveTag`. Правило в системный промпт: «чтобы показать/скрыть группу связанных узлов,
используй теги, а не цикл по `visible`».

### UI назначения

Быстрые пути (по убыванию скорости в изученных инструментах): всегда видимый дропдаун цели (ленточный
комбобокс слоёв AutoCAD), попап у курсора с «новая коллекция из выделения» одной клавишей (`M` в Blender),
драг цветного квадратика выделения на строку (Illustrator). У нас: мультиселект + «Move to tag ▸» в
контекстном меню дерева одной записью в историю (через `coalesceKey`), дропдаун `Tag: hud ▾` в селекшн-стрипе
Flow, «новый тег из выделения» одним действием — и главный быстрый путь в Flow это чат: «помечай руку,
стрелку и подсветку тегом Tutorial», агент заменяет попап Blender. Наследование делает 30 объектов дешёвыми:
пометил родителя — готово.

## Что отвергнуто навсегда (не возвращать при разморозке)

- Мульти-членство для видимости (см. доказательства выше).
- Порядок отрисовки по тегам — никогда: остаётся дерево + `zIndex`; позиция чипа косметическая, и
  drag-reorder на стрипе не делаем, чтобы он не обещал z-порядок.
- Связь тега с cull-масками камеры, физическими слоями и raycast-фильтрами: в Unity/Godot/Cocos это главный
  генератор «почему мой объект не рендерится», плюс дефицит 32 слотов на рендер+физику. Unreal намеренно
  **не** переиспользует организационные слои для рендера — и у него меньше всех таких тредов.
  Под физику отдельно зарезервировать `collisionLayer`/`collisionMask` (в 2D-физике v1 их нет,
  [../TODO.md](../TODO.md)), нынешний фильтр — пер-хитбоксовый `group` в `Collision2DService`, а не `node.groups`.
- Персист авторской маски в `.pix3scene` (Godot `_edit_lock_` в `.tscn`, Unreal Layers в `.umap` — обе
  практики дают «скрытое уехало к коллегам»).
- Отдельная док-панель «Tags» в отдельном окне: главная причина смерти панели Layers в Unreal — она жила
  в закрытом по умолчанию окне, и скрытое состояние не было видно оттуда, где работают. Стрип — там же, где
  сцена.

## Сводка прошлого опыта (чтобы не пере-исследовать при разморозке)

| Инструмент | Единица группировки | Редакторский канал | Отгружаемый канал | Solo | Где живёт набор |
| --- | --- | --- | --- | --- | --- |
| Unity | `Layer` int 0–31, одиночный, без наследования (+ Tag, Sorting Layer, Rendering Layers — четыре разных «слоя») | Scene Visibility (глазик/`H`) в `Library/SceneVisibilityState.asset`, вне VCS; дропдаун Layers в тулбаре | `SetActive`, `Renderer.enabled`, `cullingMask` | `Shift+H`, временный оверрайд поверх маски, откатывается | проект (`TagManager.asset`) |
| Godot 4 | `groups` мульти (без видимости) + `visibility_layer` 20 бит, без наследования | **нет** (глазик пишет `visible`); `_edit_lock_` метадата уезжает в `.tscn` | `visible` | нет; proposal #7451 просит именно наш дизайн | имена слоёв — проект, группы — сцена |
| Cocos 3.x | `node.layer` один бит, без наследования | **нет** (только lock) | `node.active`, `Camera.visibility` | нет | проект |
| Unreal 5 | Layers (мульти, в `.umap`), Outliner folders, Data Layers (Asset + Instance) | глазик аутлайнера `bHiddenEdTemporary` — только сессия, не сохраняется (UE-947 с 2015); панель Layers — **сохраняется в карту** | `bHidden`; Data Layer `InitialRuntimeState` | `Shift+H` / `Ctrl+H` | слои — уровень, Data Layer Asset — проект |
| GameMaker / Construct 3 | слой комнаты / лэйаута, объект на одном слое | **нет** — глазик = стартовое состояние в игре | тот же флаг + `layer_set_visible` | нет | комната / лэйаут |
| Blender | коллекция (мульти, без наследования) + View Layer | глаз/`H` (пер-view-layer), монитор, чекбокс исключения | камера (disable in renders) | Local View `/`; хоткеи 1–9 убраны в 5.0 после многолетнего «всё исчезло» | файл |
| AutoCAD | именованный слой (плоский, поперёк блоков) | Off / Freeze / VP Freeze / Lock | колонка **Plot** | `LAYISO` — по умолчанию **гасит и лочит**, не скрывает; `LAYUNISO` возвращает | чертёж |
| Figma | дерево/фреймы | глазик — **шарится на всех редакторов**, просьбы про персональную видимость висят годами | тот же глазик (скрытое не идёт в прототип и экспорт) | нет | документ |

Почему панель Layers в Unreal заброшена (самый ценный датум всего исследования): жила в отдельном
закрытом окне; сохраняла видимость в общую карту; пользователи ждали влияния на игру, а его нет; папки
Outliner закрыли 90% нужды в панели, которая уже открыта; плоская, без цветов, не знает про спавн и аттач;
Epic объявила Data Layers заменой. Вывод: **таксономия, конкурирующая с деревом и не видимая с места
работы, отмирает.** У Pix3 в Flow дерева нет — единственная конфигурация, где у фичи нет заменителя.

## Объём при разморозке

Рантайм: `nodes/NodeBase.ts` (`tag` в схеме + реактивная установка, `effectiveTag`), новый
`core/scene-tags.ts` (состояние, парсинг `metadata.tags`, API), `core/SceneService.ts` (`get tags()`),
`core/SceneRunner.ts` (`startsHidden` в `runGraph`, dirty-refresh в тике), `core/SceneManager.ts`, `index.ts`.
Редактор: `features/tags/` (upsert/rename/delete/assign — все undoable), хук на `layer`/`tag` в
`UpdateObjectPropertyOperation`, редактор тегов (поповер «Manage»), строка `Tag` в инспекторе (нужен
`optionsProvider` в property-schema — статический `options` не подходит), точка и затемнение в дереве,
`AgentToolRegistry` (`tags`, фильтры), `AgentChatService` (строка контекста).
Документация: раздел «Scene Tags» в `docs/pix3-specification.md` рядом с Groups Engine, строка в
`docs/nodes-and-systems.md` и в справочнике `NodeBase`.

Итого **+700–900 строк** поверх фазы 0.
