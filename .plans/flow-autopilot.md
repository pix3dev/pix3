# Flow Autopilot — автономный режим прототипирования

**Дата:** 2026-09-20. **Статус (ревизия 2026-09-24):** основа фазы A реализована,
но её приёмка (три последовательных автономных инкремента) не пройдена. Перед фазой B нужен
этап A1 — укрепление супервизора. Фазы B и C не завершены.
**Авторы:** сессия + Fable (архитектурная часть), постановка и развилки — пользователь.
**Родитель:** [prompt-to-playable-flow.md](prompt-to-playable-flow.md) — этот план уточняет его
принцип 1 («не вся игра за один промпт») и принцип 3 («агент может спрашивать») для случая,
когда человека **нет за клавиатурой**.

Постановка пользователя (2026-09-20): «режим создания прототипа, который не требовал бы так
много ответов в процессе, а приходил бы автономно к подобному результату. Например, если
пользователь не отвечает в течение 15 секунд или выбирает "продолжи автономно", он будет
выбирать ответы сам или использовать советника (если он задан)».

## 1. Что на самом деле стоит дорого (разбор `data/agent_logs/flappy_bird.json`)

Лог — **один инкремент** Flow на лане `agy`: пользователь прислал багрепорт («после проигрыша
экран пульсирует красным непрерывно»), агент за 26 ходов нашёл причину (`TouchRules` висит на
`game-root`, не входит в `freezeNodes` рецепта и после `lives<=0` продолжает звать
`scene.juice.flash` каждые 0.8 с) и починил её тремя точечными правками.

Что из этого следует для автономии:

| Наблюдение в логе | Вывод |
| --- | --- |
| Вопросов `ask_user` за весь инкремент — **ноль** | Авто-ответ на вопросы — не главная статья. Он нужен, но он дешёвый хвост |
| Следующий шаг («почини пульсацию») задал **человек** | Главная статья — **кто порождает инкремент**. Это и есть предмет режима |
| Баг достижим бездействием: дрон падает, `lives→0`, экран мигает | Этот класс ловится **кодом**, без модели и без vision: дойти до терминального состояния и сравнить два кадра |
| Три повторных `read_errors` с идентичным результатом, эскалация `[Pix3] You are stuck: call ask_advisor NOW` | Цикл уже умеет вмешиваться сам; автономия — расширение этого механизма, а не новый |
| Три `find_nodes` подряд вместо одного `batch` | Автономия **умножает** неэффективности ланы. Бюджет хопов обязателен |

**Центральное решение:** автопилот — это **супервизор в коде**, а не «режим промпта». Модель
исполняет инкремент, код решает, какой инкремент следующий, и код же судит результат.

## 2. Три роли, один артефакт

### 2.1 Очередь — существующий `design/progress.md`, второго источника истины не заводим

Формат уже есть и уже парсится: `renderProgressMarkdown`
([PrototypeBootstrapService.ts:2551](../src/services/flow/PrototypeBootstrapService.ts#L2551))
пишет `- [ ]` / `- [~]` / `- [x]` из `brief.increments` + `brief.wow`, `parseChecklist`
([FlowPlanService.ts:129](../src/services/flow/FlowPlanService.ts#L129)) их читает, side-panel
рисует. Заводить второй файл нельзя — «два источника истины» уже били по активной сцене.

Два расширения формата, оба переживаемы текущим парсером (он видит их как обычные пункты):

- секция `## Found by playtest` с пунктами `- [ ] FIX: <дефект> — <путь к отчёту>` (фаза B);
- хвост ` _(auto)_` у пункта, взятого супервизором без человека → поле `auto` в `FlowPlanStep`.

### 2.2 Роли

| Роль | Кто | Ответственность |
| --- | --- | --- |
| **Режиссёр** | новый `FlowAutopilotService` (код, без модели) | выбор следующего шага, запуск хода, таймер, бюджет, стоп-критерии |
| **Исполнитель** | существующий цикл [AgentChatService](../src/services/agent/AgentChatService.ts) без изменений логики | один инкремент за ход + verify-гейт (`FLOW_VERIFY_ATTEMPTS = 3`) |
| **Плейтестер** | новый `FlowPlaytestService` (код, зовёт хендлеры тулов напрямую, минуя модель) | smoke-suite после инкремента → `FIX:`-пункты (фаза B) |

### 2.3 Приоритет следующего шага (детерминированный, без модели)

1. Сообщение человека — всегда перебивает.
2. Открытый `FIX:` класса **P0** (crash / `newErrors` / состояние, из которого игра не выходит /
   нечего нажимать).
3. Незакрытый `- [~]` (verify-гейт не дал закрыть ход честно) — доделать его.
4. Первый `- [ ]` основного списка.
5. `FIX:` класса P1 (визуальные, эвристические).
6. Пункты `wow` (spectacle beats).
7. Ничего из перечисленного → **«прототип готов»** (§5).

Промпт хода строит код по образцу `renderFirstTurnMessage`
([PrototypeBootstrapService.ts:2809](../src/services/flow/PrototypeBootstrapService.ts#L2809)):
один инкремент, доказать прогоном, обновить `progress.md`. Свежий разговор с хэндоффом при
разрастании контекста уже работает (`flowIncrementHandoff`).

### 2.4 Плейтестер: что ловится кодом, а что нет (фаза B)

| Проверка | Инструмент (существует) | Ловит |
| --- | --- | --- |
| Ошибки скриптов | `read_errors` | падения |
| Обезьяна на сиде | `game_run {monkey:{seed}, until:[{kind:'frames',n:1800}], fail:[{kind:'newErrors'}]}` | crash под вводом; `monkey-empty` = «игра неинтерактивна» |
| Живость сцены | `game_observe` с окном без ввода → `verdict`/`activity` | мёртвая сцена, спавнер не спавнит |
| **Терминальное состояние** | `game_run` по `phase`/`outcome` из контракта рецепта или игры, под бездействием и вводом | класс из flappy-лога: «агент не доиграл до поражения»; отсутствие достижимого исхода = `inconclusive` |
| **Пост-терминальная устойчивость** | 120 кадров с инвариантом `phase`, проверка restart; несколько `viewport_screenshot` по контракту статичных областей | застрявшее состояние, ошибки после исхода, пульсация вне разрешённой анимации; пиксельная эвристика без контракта = `CHECK`, не P0 |
| Контроли | `game_controls` + негативный контроль (`control:{tap:{nx,ny}}`) | мёртвые и перекрывающиеся кнопки |
| Регрессии | `game_run {routine}` по `design/tests/routines/*` | поломка прошлых инкрементов |

**Слепые зоны, названные честно.** Верификация состоянием слепа к ориентации и к «похоже ли это
на игру» ([TODO.md](TODO.md), находка 2026-08-29: тетрис ронял фигуры **вверх** при полностью
зелёных проверках). Единственный дешёвый инструмент — **один `analyze_image` на инкремент** с
фиксированной рубрикой да/нет. Он шумный (зафиксировано `ok:true` на пустом кадре), поэтому его
вывод — только `CHECK:`-пункты P1, **никогда** не стоп-критерий и не перебивание очереди
(фаза C). Частично ориентация ловится кодом, если рецепт объявит `gravityAxis` в контракте.

## 3. Режимы, триггеры, перехват

### 3.1 Три режима

- **Interactive** — как сегодня, дефолт. Кнопка «Продолжить автономно» всегда на виду.
- **Assisted** — после первого нажатия кнопки: в конце каждого хода идёт видимый отсчёт;
  истёк — режиссёр берёт следующий шаг.
- **Autonomous** — тумблер до первого промпта: ожиданий нет вообще, `ask_user` не завершает ход,
  а отвечается маршрутизатором внутри хода (вход с первого промпта — фаза C).

### 3.2 Автомат (`appState.ui.flowAutopilot`)

`off → armed → countdown → running → (countdown | paused | done)`

- **countdown** стартует на переходе `AgentChatStatus` `running → idle` — один и тот же момент,
  что и появление вопроса, но покрывает и ход **без** вопроса.
- `status === 'error'` → **paused**: ошибка провайдера не повод крутить бюджет.
- Отсчёт **паузится** (не сбрасывается) на ввод в композере и активность в чате; возобновляется
  с остатка. Esc → `off`.
- **Скрытая вкладка** — отсчёт идёт: это ровно «пользователь ушёл», ради чего режим и нужен.
  Защищает не таймер, а бюджет (§5).
- «Взять руль» = `chat.stop()` + `mode = 'off'`; временные правки откатываются существующим
  `revertTemporaryEdits` в `finally`.
- Сообщение пользователя во время `countdown` отменяет запланированный `send` и уходит обычным
  путём.

### 3.3 Пороги: **15 с — это opt-in, а не дефолт**

Два разных порога, оба настраиваемые:

| Что | Порог | Почему |
| --- | --- | --- |
| Следующий инкремент | **15 с** | низкие ставки: очередь — это план самого пользователя из брифа |
| Ответ на `ask_user` в Assisted | **45 с** | высокие ставки: тул по контракту зовётся там, где «угадать неверно = перестраивать» |
| Autonomous | **0 с** | там вопросы решает маршрутизатор, ждать некого |

Обоснование порога — §7.1.

## 4. Кто отвечает на `ask_user`

Маршрутизатор — чистая функция `autopilot-router.ts`, четыре шага по убыванию надёжности:

1. **Вопрос уже есть в `design/decisions.md`** (нормализованное совпадение) → повторить выбор.
   После компакции модель переспрашивает уже решённое; это бесплатная победа и первый источник.
2. **Дефолт из брифа/рецепта** — вариант, совпадающий с `brief.md` / `recipe.md`
   (`source: 'auto-brief'`).
3. **Советник**, если задан (`AgentAdvisorService.consult`) — один stateless вызов: бриф +
   решения + вопрос + варианты; ответ обязан быть **индексом варианта**
   (`source: 'auto-advisor'`, фаза C).
4. **Иначе сам агент, без лишнего хопа**: в автономном режиме `ask_user` не завершает ход —
   хендлер возвращает `{answered: null, by: 'self', options}` с инструкцией выбрать самому,
   назвать выбор одной строкой и продолжить; `pass.askedQuestion` не выставляется, цикл идёт
   дальше (`source: 'auto-agent'`).

Эвристика «первый вариант» **не нужна**: порядок вариантов модель задаёт произвольно, а шаг 4
всегда достижим и стоит ноль хопов. Советник не задан — шаг 3 просто пропускается (советник по
умолчанию выключен и авто-назначается только при нулевой предельной стоимости).

**Пометка и откат.** `DecisionEntry` ([decision-log.ts:25](../src/services/flow/decision-log.ts#L25))
получает `source: 'user' | 'auto-brief' | 'auto-advisor' | 'auto-agent'`; `formatDecisionLine`
рендерит ` _(auto: brief)_` перед датой, парсер понимает. Замена строки по тому же вопросу уже
реализована (`record_decision` REPLACES). Карточка авто-решения в чате держит остальные варианты
чипами; клик шлёт обычное сообщение «измени решение» — это **один инкремент**, а не пересборка.
Честно: если авто-решение структурное и после него прошло три инкремента, смена стоит
инкремент-два — поэтому карточка появляется **в момент** решения, а не только в финальном отчёте.

## 5. Ограничители и критерий «готово»

**Бюджет забега** (настройки, дефолты): ≤ 6 инкрементов, ≤ 240 тул-итераций суммарно,
≤ 20 мин wall-clock, ≤ 600K **некэшированных** входных токенов (дельта
`totalUsage.inputTokens − totalUsage.cacheReadTokens` по разговорам). Счётчик ходов включает
ответ на `ask_user`, поэтому его нельзя выдавать за число построенных инкрементов. Деньги — только **оценка**
(«≈ $x»): каталог помечает цены как indicative, обещать точную сумму нельзя.

**Досрочная пауза (→ `paused` + отчёт):**

- verify-гейт закрыл ход честным провалом два инкремента подряд;
- один и тот же `FIX:` вернулся после **двух** попыток — это гард против «уверенно чинит не то»:
  третья попытка не даётся, зовётся человек;
- loop-breaker эскалировал дважды за инкремент или сработал `forcedOverwrites`;
- сцена не стартует (`play_status` не доходит до running).

**Никогда автономно** (денилист поверх существующего механизма `allowedTools` в `runLoop`):
сборка/публикация HTML, `fs_delete`, `fs_write` с `overwrite:true` для файлов, которых агент не
создавал в этом забеге, правка `design/brief.md`. **`generate_asset`** — «до N за забег», дефолт
**0** (BYOK-деньги + шум), с честным предупреждением в UI, что без него кадр останется
прямоугольниками — это главная статья разрыва рубрики подачи.

**Критерий «готово»:** в основном списке `progress.md` нет `- [ ]`, нет открытых `FIX:` P0,
последний smoke-suite зелёный. `wow` и `CHECK:` не блокируют. Критерий — **очередь + код**,
никогда не слова агента «Done!».

## 7. Риски и опровержения

### 7.1 15 секунд как дефолт — плохо; как opt-in — хорошо

Инкремент стоит ~26 хопов ≈ 2–4 мин на мосту (холодный старт 5–10 с, тёплый хоп 2–3.5 с,
~0.11 с на 1K токенов — §11.8 родительского плана). 15 с ожидания — меньше 10 % инкремента и не
там, где vibe проигрывает эталону в 6–16× ([done/vibe-vs-chat-gap.md](done/vibe-vs-chat-gap.md)).
Зато прочитать резюме хода с тремя вариантами дольше 15 с, а неверная структурная развилка стоит
инкремент-два. Поэтому: 15 с только после явного «арминга», для `ask_user` — 45 с. Включённые по
умолчанию 15 с начали бы перебивать думающего пользователя и нарушили бы принцип 3.

### 7.2 Автономия усиливает измеренный класс «агент уверенно чинит не то»

Три задокументированных случая: машина ехала боком после четырёх слепых переписываний
(`agent-car-direction-regression`); тетрис ронял фигуры вверх при зелёной верификации состоянием
(TODO, находка 2026-08-29); страйкер каррома на чужой базовой линии прошёл `tsc`, prettier,
YAML-валидацию, headless `parseScene` и геометрические проверки
([carrom-agent-pipeline-review.md](done/carrom-agent-pipeline-review.md) §3). Все три поймал прогон
поведения или человек глазами. Отсюда: судья — код; две попытки на дефект, потом пауза.

### 7.3 Потолок режима

Автопилот доводит до «нет дефектов известных нам классов», а не до «хорошая игра». Подача и
«весело ли» остаются за человеком и за шумной vision-рубрикой. Отчёт обязан говорить это прямо.

### 7.4 Человек в логе нашёл баг, потому что доиграл

Обезьяна и «дойти до терминального состояния бездействием» покрывают flappy-класс дёшево, но не
игры, где проигрыш требует навыка — там suite честно ставит `CHECK`, а не притворяется.

### 7.5 Экономика

Забег из 6 инкрементов ≈ 150 хопов, 15–25 мин, на метерном провайдере — заметные деньги без
точного счётчика. Плейтест почти бесплатен (код), vision — один вызов на инкремент. Лана `agy`
делает строго один тул на сообщение и повторяет вызовы — для неё разумнее Assisted, а не
Autonomous.

### 7.6 Конфликт с пользователем и загрязнение лога решений

Отсчёт паузится на ввод, любое сообщение отменяет `send`, «Взять руль» = `stop()` — иначе режим
ощущается как отбирающий чат. Авто-строки в `decisions.md` читает планнер при каждой компакции;
спасают пометка `source`, замена по вопросу и список в отчёте.

### 7.7 Что осознанно не делаем сейчас

Headless-раннер сцен ([carrom-agent-pipeline-review.md](done/carrom-agent-pipeline-review.md)) сделал
бы плейтест кратно дешевле, но это отдельный L. Автопилот работоспособен на in-editor `game_run`.

### Этап A1 — укрепление супервизора перед плейтестером (обязательный)

1. Передавать супервизору типизированные события исполнения и итог хода: реальные итерации и
   вызовы инструментов, исход verify-гейта, неудачи запуска, эскалации loop-breaker, вынужденные
   перезаписи, созданные файлы и платные задания. `activeTool` — UI-сигнал, не источник учёта.
2. Проверять лимиты **во время** хода: на один ход и на забег. При достижении лимита остановить
   ход через `chat.stop()`, дождаться отката временных правок и показать конкретную причину.
   Положительный лимит `generate_asset` резервировать до вызова и расходовать по всему забегу.
3. На уровне исполнения, включая `batch`, запретить правку `design/brief.md`, `fs_delete` и
   `fs_write overwrite:true` для файлов, не созданных в этом забеге. Проверить все доступные
   пути записи, а не только список тулов, показанный модели.
4. При `Take the wheel`, смене проекта и `dispose()` инвалидировать ожидающие таймеры и

**Приёмка A1:** застрявший ход останавливается до исчерпания общего бюджета, временные правки
откатываются; после перехвата или смены проекта старый ход не стартует; платная генерация N+1
отклоняется до расхода денег; запреты работают и в `batch`. Затем повторяется приёмка A.

### Фаза B (M) — плейтестер

`FlowPlaytestService` (ошибки, обезьяна, терминальное состояние, пост-терминальная устойчивость,
контроли, routines) → секция `## Found by playtest`, перебивание очереди и отчёт по забегу.
Проба имеет фиксированный seed, лимит кадров и исход `passed / failed / inconclusive / skipped`;
плейтестер эксклюзивно владеет runtime между ходами и восстанавливает состояние в `finally`.
Терминальное состояние, restart и допустимая анимация после проигрыша задаются рецептом или
тестовым контрактом: `lives` не универсально. Несколько кадров и контракт неподвижности нужны,
потому что diff двух кадров может совпасть по фазе или принять разрешённую анимацию за дефект.
`FIX:` получает устойчивую подпись, версию сцены, ссылку на отчёт и число попыток; галочка агента
не закрывает воспроизводимый P0. Последний smoke-suite обязателен перед `ready`, даже если очередь
пуста; `wow` и `CHECK:` готовность не блокируют.
**Критерий:** внедрённая пульсация находится без человека, исправленная сцена проходит, а
разрешённая анимация не становится P0.

### Фаза C (M/L) — суждение и вход

Vision-рубрика (`CHECK:`), советник в маршрутизаторе, Autonomous с первого промпта (пропуск
стадии идеи), карточки «изменить решение», ≈$-бюджет, `gravityAxis` в рецепт-контракте.
**Приёмка:** вход с первого промпта не требует ответа; таймаут или неверный ответ советника
переходит к агенту; не больше одного vision-вызова на инкремент; `CHECK:` не блокирует `ready`;
изменение авто-решения создаёт обычный инкремент; стоимость явно помечена как оценка.
