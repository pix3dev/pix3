# Vibe: «вау» после первых промптов

Цель (постановка 2026-09-21): пользователь вводит одно ТЗ, и после первых промптов получает
прототип, который **не стыдно показать и приятно дорабатывать** — стиль с первого кадра,
приличный UI, частицы/VFX, твины, fade/cross-fade, и никаких оверлеев поверх кор-механики.
Метод: разработчик-наблюдатель ведёт агента через Vibe на реальном ТЗ, смотрит каждый шаг,
прерывает и правит редактор/движок, повторяет. ТЗ-полигон: idle-пинбол «Каскад»
(`C:\Projects\MyLabs\archive\jam-august\ideas\07-kaskad-idle.md`).

Связано: [flow-autopilot.md](flow-autopilot.md) (супервизор), [done/flow-wow-t0.md](done/flow-wow-t0.md)
(вау-пол T0), [vibe-uikit-first-frame.md](vibe-uikit-first-frame.md) (UI-кит на T0).

## Итерация 1 — базовый замер (2026-09-21, Opus 4.8 через мост)

Промпт: абзац из ТЗ (три типа деталей, мёрдж, экономика, «портрет, неон, очень сочно»).

| Этап | Время | Что вышло |
| --- | --- | --- |
| Идея, ход 1 | 32 с | название, GDD заполнен, **один вопрос** (расстановка); картинок нет |
| Идея, ход 2 | 15 с | ещё один вопрос (цель прогрессии) — лесенка вопросов |
| Идея, ход 3 (по просьбе) | 85 с | три фейковых стор-скриншота, хорошие; вопрос «какой стиль» |
| Капля «сделать стилем» | ~1 с | `style.md`, палитра **#564979 #003f65 #01507d #4d2400 #3b004b** — мутная |
| Start prototype | ~20 с | планнер выбрал **`recipe-blank-2d`**; первый кадр — серая доска, `SCORE 0` |
| Инкремент 1 | ~9 мин, 114 сообщений, 5.0M input (4.8M из кэша) | 27 `engine_search` + 7 `engine_read` до первой строки; шарик и бамперы — `ColorRect2D`-квадраты; тап ставит бампер, удар платит +5 |

Что увидел человек: стена карточек `engine_search`/`engine_read` в чате; квадратный шарик.

### Диагноз (по одному на находку)

1. **Стиль не показывается сам.** `idea-stage` откладывал мудборд до «когда разговор дойдёт до
   внешнего вида»; сами скриншоты получаются убедительными за ~25 с каждый.
2. **Лесенка вопросов.** По одному структурному вопросу за ход, без картинок — каждый ход,
   который надо ответить до того, как что-то увидишь, пользователь может не сделать.
3. **Палитра — средние по покрытию.** Median-cut на 5 коробок отдаёт четыре оттенка фона и
   одно среднее всего остального; роли `paletteColorForRole` получают грязь.
4. **Планнер отдал шар «пустому» рецепту.** Блёрб blank перечислял «physics contraptions, idle
   games», правило «механика должна пережить первый инкремент» читалось как «нет весла — не
   bouncer». А bouncer уже даёт неоновый bloom, круглый шар, бамперы с джусом.
5. **Пустой рецепт советовал квадраты**: «start with `ColorRect2D` blocks», без post-fx, без
   форм-плейсхолдеров; плюс устаревшее «в движке нет rigidbody-солвера» (в blank и bouncer),
   хотя `scene.physics2d` влит 2026-09-07.
6. **Агент не знает API и ищет исходники** — `pointerEvents`, `position.set`, `adoptChild`
   стоят 34 хопа. Доки (`nodes-and-systems.md` §4–5) всё это описывают, но в промпте их нет.
7. **UX чата**: каждый хоп — своя карточка «Working · 1 step» + строка метрик.
8. **Нет твинов в движке** (только `popIn`/`punchScale`/`core:Fade` и клипы), нет шлейфа —
   а ТЗ просит «шлейф у шарика», пользователь — «tween-анимации, cross-fade».
9. Мелочи: `batch` отказал `add_component`-шагу (агент собрал batch неправильно и потерял
   хоп); в `decisions.md` ответ «в свободной форме» записан целиком вместе с просьбой про
   скриншоты; имена файлов в записи стиля потеряли подчёркивания (`stylebsynthwave.png`).

### Что сделано после итерации 1

- **Идея, первый ход**: `renderIdeaFirstTurnMessage` + `idea-stage.md` §3/§6 — три фейковых
  стор-скриншота ЭТОЙ игры (`mood-1..3`, `role: style-candidate`) в первом же ходу, **ровно
  один** `ask_user`; картинки — второй вопрос через каплю на карточке.
- **Палитра**: `extractStylePalette` = median-cut на 16 коробок → `pickStylePalette`: фон = по
  покрытию, акценты = насыщенность × светлота × покрытие^0.35, разнос по тону ≥ 28°, исключение
  оттенков фона; порядок под индексы `paletteColorForRole` (последний = самый яркий акцент).
- **Планнер/каталог**: блёрб bouncer покрывает пинбол/плинко/пеггл/idle-пинбол «даже без весла»,
  blank — «idle без шара»; правило планнера: «переживает» = физика и облик, не каждый контрол.
- **Пустой рецепт**: `post-fx` (bloom+vignette, тюнабл `bloomIntensity`) и `bg-glow`
  (радиальный градиент под палитру) в сцене; библиотека форм `sprites/ph-{circle,orb,ring,
  star,capsule,bg}.png`, тонируемая на T0 по ролям; контракт: «круглое — `ph-circle`,
  `ColorRect2D` — только панели/полосы»; физика → `scene.physics2d`. В bouncer — честная
  заметка про движковый солвер и вариант idle (дрен перезапускает шар, весло опционально).
- **Карта API** `agent-skills/engine-api-map.md` — в кэшируемом префиксе системного промпта
  (и как скилл для чтения после компакции): Script/Node/Node2D/scene.*/input/physics2d/
  collision2d/juice/audio/поведения/ловушки, с правилом «не искать то, что здесь названо».
- **Чат**: подряд идущие хопы-инструменты сливаются в одну карточку (метрики
  агрегируются), `engine_*` → «Researching», гистограмма по инструментам для групп ≥ 4 шагов,
  такие группы по умолчанию свёрнуты.
- **Рантайм**: `scene.tween` (to / crossFade / fadeIn / fadeOut / killAll, изинги из
  `easing.ts`, scaled time) и `scene.juice.trail(node, opts)` — см. отчёт в журнале ниже.

Продолжение (первый ход перезапущен через автопилот, без Project map в сообщении):

| Этап | Время | Что вышло |
| --- | --- | --- |
| Инкремент 1 (автопилот, ход 1) | ~12 мин, ~40 хопов | витрина «БАМПЕР · 25» (UI-кит), свободная расстановка тапом, конвейер перезапускает шар, удары платят; доказано `game_run`. Поисков по движку: **4 `engine_search` + 1 `engine_read`** (сигналы `Button2D`, `registerGameDebug` — их не было в карте, дописаны) против 27+7 в итерации 1 |
| Инкремент 2 (автопилот, ход 2) | ~6 мин, ~25 хопов | магнит (тап — поворот 45° и выстрел) и реле (заряд 10 с, выплаты), две новые кнопки витрины; доказано в игре; **0** поисков по движку |

**Критерий приёмки фазы A автопилота выполнен**: три инкремента подряд без единого сообщения
человека (единственное вмешательство — перезапуск хода 3 после моей же перезагрузки).

Палитра после доработки (акценты из цветных пикселей, фон не чёрная рамка): mood-2 →
`#363d55 #a25282 #597cd1 #f0c959 #3eb8c8`, mood-1 → `#18182d #e8bf4c #42d270 #cd61d9 #56cee3`.
Замерено на реальных картинках, но в T0 этого прогона ещё уехала старая мутная палитра —
бамперы почти чёрные на тёмно-синем. Нужна итерация 3 с нуля.

Ход агента через мост: ~45 с на хоп при 100–300 выходных токенах («Thinking…») — темп
ограничен моделью/ланой, не редактором.

Новые находки:
- **`batch` терял хоп в каждом ходу дважды.** (а) Первый вызов приходит с недопарсенным вводом
  (`__unparsedToolInput`, обрывок `<parameter name="onError">` вместо JSON) — это артефакт
  Claude Code SDK (`claude.exe`) на стороне моста, повторяется в каждом ходу первым `batch`;
  (б) модель пишет имена шагов как `mcp__pix3__fs_read` (так тулы называются через мост), а
  реестр знает только голые имена → «Unknown tool». (б) исправлено: `normalizeBatchToolName`
  срезает префикс `mcp__<server>__`. (а) — кандидат: мост должен превращать недопарсенный
  ввод в понятную ошибку «input did not parse, resend» вместо пустого объекта.
- **Мокапы «в телефоне»** — красиво, но палитра меряется с чёрной рамки. Скилл и первый ход
  теперь требуют full-bleed экран без корпуса/рамки/фона.
- ~~Капля снимает висящий вопрос~~ — ложная тревога: чипы снесла HMR-перезагрузка от моих
  правок (вопрос `ask_user` живёт только в памяти страницы). Мелкий кандидат на устойчивость:
  переживать перезагрузку вместе с историей чата.
- **Первое сообщение хода на bouncer = 92K символов.** Бюджет `PROJECT_MAP_BUDGET_CHARS`
  90K задуман против десяти `fs_read`, но на модели уровня Opus даёт минуты «Thinking…» до
  первого действия. Кандидат: инлайнить только `design/*.md` + сигнатуры/шапки скриптов,
  а полный код оставлять для `fs_read` по требованию; замерить обе стороны.
- **Правило сессии:** не редактировать `src/` во время живого прогона (HMR = reload = потеря
  хода). Записано в память.
- После T0 `style.md` без строки `Reference:` — смена стиля не снимала роль с прежнего файла
  (два `style`). Исправлено в `renderStyleMarkdown`.

## Открытые пункты / следующие итерации

- **Палитра, тюнинг яркости акцентов** (см. итерацию 3) — главный оставшийся рычаг первого кадра.
- Первый `batch` каждого хода приходит недопарсенным (`__unparsedToolInput`, артефакт Claude Code
  SDK в мосте): мост должен вернуть модели «input did not parse — resend as JSON» вместо `{}`.
- Темп моста: ~45 с/хоп при 100–300 выходных токенов, крупный `str_replace` — 4 мин.
- Незавершённый ход и `ask_user` не переживают перезагрузку страницы.

- Итерация 2: тот же промпт с нуля; замерить время до первого кадра, число хопов на первый
  инкремент, доля поисковых хопов, качество первого кадра глазами.
- Стоп-критерий «кап хопов на ход» в автопилоте (из [flow-autopilot.md](flow-autopilot.md)).
- `batch` с `generate_asset`: три скриншота идут последовательно (~85 с) — параллельная
  генерация внутри одного вызова срезала бы минуту первого хода.
