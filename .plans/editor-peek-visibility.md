# Peek: неразрушающее скрытие групп объектов в редакторе (фаза 0)

**Статус: в работе.** Записано: 2026-09-10. Сложность: M.
Продолжение — [frozen/scene-tags-visibility.md](frozen/scene-tags-visibility.md) (фаза 1, теги как самостоятельная
таксономия), она заморожена **до выполнения критериев разморозки**, перечисленных в том плане.

## Проблема

Видимость логически связанной группы объектов сегодня переключается только поштучно и только через дерево:
глазик у узла пишет `visible` в `.pix3scene`. В **Flow** дерева нет вообще (`src/ui/flow/pix3-flow-shell.ts` —
чат + живая сцена + опциональный `pix3-flow-scene-view`; инспектор-drawer есть, `appState.ui.flowInspectorOpen`,
[pix3-flow-scene-view.ts:96](../src/ui/flow/pix3-flow-scene-view.ts#L96), но он поштучный и требует **кликнуть**
объект — а объект, закрытый другим экраном, кликнуть нельзя). Практический сценарий, который сегодня не
обслуживается: агент собрал три перекрывающихся UI-экрана, и человеку нужно посмотреть, что под ними, не
разбирая сцену и не трогая файл.

## Решение фазы 0: один канал, ноль новой таксономии

**Peek — авторская маска видимости.** Пер-юзерское, несериализуемое, вне undo состояние «что я сейчас
не хочу видеть». Не игровое состояние, не свойство узла, не запись в сцену.

Ключевое отличие от первоначального дизайна: **никакой таблицы слоёв и никакого нового свойства узла в
фазе 0.** Чипы выводятся автоматически из структуры, которая в сцене уже есть. Обоснование — в разборе
прошлого опыта (ниже): у playable-ad несколько десятков узлов и 3–5 очевидных групп, которые **уже
являются родительскими узлами**, а вторая таксономия поверх дерева — ровно тот класс фич, который в
Unreal (панель Layers) отгрузили и забросили.

### Что уже есть и что нельзя дублировать

| Существующее | Что делает | Почему это не Peek |
| --- | --- | --- |
| `visible` / `initiallyVisible` ([NodeBase.ts:742-772](../packages/pix3-runtime/src/nodes/NodeBase.ts#L742)) | авторская и стартовая видимость узла | сериализуется — авторское «подсмотреть» уедет в билд |
| `editorOnly` (`SceneRunner.stripEditorOnly`) | аннотации: видно при авторинге, вырезано из игры | про содержимое сцены, а не про сессию |
| `groups` ([NodeBase.ts:516](../packages/pix3-runtime/src/nodes/NodeBase.ts#L516)) | мульти-теги для `getNodesInGroup`/`callGroup` | логика/запросы, без семантики видимости |
| `CanvasLayer2D`, `zIndex` | полоса отрисовки и порядок | Peek порядок не меняет **никогда** |
| Фильтры «2D/3D» (`ToggleLayer2DCommand`) | фильтр размерности вьюпорта | это не «слои» — переименовать (см. ниже) |

## Механизм

Эффективная видимость считается в одном месте — аксессором на `NodeBase`:

```ts
private selfVisible = true;      // инициализатор обязателен: useDefineForClassFields: true в
                                 // packages/pix3-runtime/tsconfig.json:4
/** Ставится PeekService/SceneRunner'ом; НИКОГДА не сериализуется. */
hiddenByEditor = false;

override get visible(): boolean { return this.selfVisible && !this.hiddenByEditor; }
override set visible(v: boolean) { this.selfVisible = v; this.properties.visible = v; }
```

Почему так, а не иначе:

- **Дёргать `visible` напрямую** — отпадает: пишет авторское решение в файл (в Flow есть debounce-автосейв
  в `pix3-flow-scene-view`, так что уедет само) и затирает собственный флаг узла — класс багов, из-за
  которого `ViewportScreenshotter.withNodeIsolation` таскает `saved`-мапу.
- **`layers.mask = 0`** — ловушка: three проверяет слои **поштучно и без наследования** (ранний выход в
  `projectObject` только по `visible === false`), значит надо штамповать каждый потомок, включая меши из
  async-GLTF и лейблы `UIControl2D`; `Node2D.add` перештампует; биты 0–3 заняты полосами
  ([constants.ts](../packages/pix3-runtime/src/constants.ts)); а `isVisibleInTree()` и пикинг читают
  `.visible` — скрытый HUD продолжит съедать тапы.
- **Аксессор** покрывает все пути даром: 3D-узлы в редакторе **настоящие**
  ([Viewport3DContentSync.ts](../src/services/viewport/Viewport3DContentSync.ts) `.visible` не трогает),
  2D-прокси зеркалят флаг ~10 раз (`root.visible = node.visible` в
  [Viewport2DProxyRegistry.ts:388](../src/services/viewport/Viewport2DProxyRegistry.ts#L388) и далее),
  плюс пикинг, `isVisibleInTree()`, гейтинг ввода `UIControl2D` и рантайм. Каскад на детей — родной
  three.js, поэтому флаг ставится только на **корни веток**, O(ветки), а не O(объекты).

Проверено перед планированием: `Object3D` присваивает `this.visible = true` обычным присваиванием
(прототипный сеттер сработает), ни один узел Pix3 не объявляет `visible` полем класса.

### Две ловушки механизма, которые обязательно закрыть

1. **Реактивный слой схемы.** Сейчас `visible` — это **per-instance** аксессор, который ставит
   [reactive-schema-properties.ts](../packages/pix3-runtime/src/fw/reactive-schema-properties.ts): он
   подменяет плоские own-поля, и запись `node.visible = false` из скрипта уходит в схемный `setValue`,
   который пишет и `properties.visible`. С прототипным аксессором own-property не создастся →
   `makeSchemaPropertyReactive` вернёт `skipped-missing`. Поэтому новый сеттер **обязан** зеркалить
   `properties.visible` сам (см. код выше), схемный `getValue` — читать `selfVisible`, а
   `reactive-schema-coverage.spec.ts` (перечисляет `visible`) — обновиться.
2. **`Object3D.clone()`/`copy()`** копируют эффективное значение. Известных потребителей нет (клон графа в
   `SceneRunner.startScene` идёт через serialize→parse), но нужен комментарий и спека.

## Откуда берутся чипы (без нового формата)

`PeekService` выводит список «веток» из активной сцены по детерминированному правилу:

1. базовый набор — узлы верхнего уровня сцены;
2. если верхнеуровневый узел один — спускаемся на уровень его детей (частый случай единственного корня);
3. всегда добавляем встреченные на первых двух уровнях корни инстансов префабов (`isPrefabInstanceRoot`) и
   `CanvasLayer2D`;
4. подпись чипа = `node.name`, идентичность для персиста = `node.id` (стабилен в `.pix3scene`), имя — фолбэк;
5. больше 8 чипов — хвост уходит в оверфлоу «+N ▾» (тот же список, поповер), стрип **не** сворачивается в
   закрытое меню целиком: провал дропдауна Layers в Unity — «состояние спрятано, и про него забывают».

Список пересчитывается на смену активной сцены и на структурные мутации графа; маска хранится по `node.id`,
поэтому переименование её не рвёт, а удаление узла — тихо отбрасывает.

## Состояние, персист, undo

- `appState.scenes.peekHiddenByScene: Record<string, string[]>` (id узлов) — рядом с `editorCameraStates`
  в [AppState.ts](../src/state/AppState.ts).
- **Персист между сессиями — localStorage по пути сцены**, не в `.pix3scene`. Unity держит пер-юзерскую
  маску в `Library/SceneVisibilityState.asset` именно поэтому; чисто сессионная маска заставляет
  перещёлкивать всё после каждой перезагрузки. В файл сцены — никогда (в Godot `_edit_lock_` в `.tscn` и в
  Unreal видимость панели Layers в `.umap` дают жалобы «скрытое уехало к коллегам»).
- **Вне undo**: операция возвращает `didMutate: true` без `commit` — `OperationService` такое не пушит
  (`commit` опционален). Причина продуктовая: в Flow человек скрывает HUD, жмёт Ctrl+Z и ждёт отмены
  правки агента, а не возврата HUD. Сам чип — себе undo. (Существующий `ToggleUIFlagOperation` для сетки
  в историю попадает; это антипример, его не копируем.)

## UI

Один компонент `pix3-peek-strip` (Light-DOM Lit, иконки через `IconService` — `eye`/`eye-off`, тема токенами).

- **Чипы с подписями**, не квадратики: у Blender 2.7x была ровно такая полоска из 20 кнопок слоёв в хедере
  вьюпорта, и её убрали в 2.80 потому, что кнопки были **без подписей** и не масштабировались.
- **Клик = toggle, ⌥-клик = solo.** Не наоборот: у Blender клик по кнопке слоя был solo, и это дало
  многолетнее «нажал 1 — всё исчезло» (в 5.0 биндинг убрали из вьюпорта).
- **Solo гасит, а не скрывает**: не-solo ветки рендерятся ~25% альфы и не пикаются. Дефолт `LAYISO` в
  AutoCAD — «lock and fade», и на него меньше всех жалоб; «всё исчезло» перестаёт быть возможным.
  Реализация: `hiddenByEditor` для скрытия, отдельный `dimmedByEditor` → множитель альфы в прокси-материалах
  и `opacity` 3D-материалов на время solo.
- **Повторный ⌥-клик возвращает предыдущий набор** (как alt-клик по глазу в Photoshop), а не «показать всё».
- **Пилюля «N hidden · Show all»** — несбрасываемая, пока что-то скрыто, и она же кнопка выхода (модель
  хлебной крошки isolation mode в Illustrator; без неё пользователи «застревают» даже при наличии индикатора).
- **Монтирование:** стейдж-бар `pix3-flow-shell` (между статусом и Play/Restart) и верх `pix3-flow-scene-view`.
  Studio (тулбар вьюпорта) — тем же компонентом, но допустимо отделить во второй PR.
- **На границе выдачи предупреждать**: Export / Download HTML / «играть как в билде» пишут «N ветвей скрыты
  только у вас — в игре они будут видны». Этого не делает ни один изученный инструмент, а это ровно
  тот failure mode, который вводит несериализуемая маска.

## Play-режим

Маска остаётся живой во время игры (это и есть главный кейс «скрыть HUD, чтобы увидеть мир»). Клон
строится через serialize→parse, поэтому маска подаётся **снаружи**: `SceneRunner.setEditorPeekMask(ids)`,
применяется в `runGraph` и переприменяется на каждый рестарт стейджа (в Flow стейдж рестартится после
каждого хода агента). В экспорт не попадает по построению — она вообще не живёт в файлах.

Побочный эффект правильный: скрытая ветка перестаёт перехватывать тапы (`UIControl2D` гейтит ввод по
`isVisibleInTree()`).

## Агент

- Новый инструмент **`peek`**: `{ action: 'hide' | 'show' | 'solo' | 'show_all' | 'list', nodeIds?, nodeNames? }`.
  В описании прямым текстом: «влияет только на вид в редакторе, никогда не попадает в игру и в экспорт;
  чтобы скрыть в игре — `set_property visible`».
- **`hiddenByEditor` в выводах**: `scene_tree`, `node_inspect`, `play_status`, `game_observe`,
  `viewport_screenshot` (рядом с существующим `hiddenByAncestor`). Без этого главный риск фичи —
  агент чинит то, что человек всего лишь замаскировал, и наоборот.
- Одна строка в блоке контекста `AgentChatService.buildSystemPrompt`: `Peek: HUD, EndCard hidden in your view`.

## Заодно (мелкий долг, снимается тем же PR)

Переименовать заголовки команд `ToggleLayer2DCommand` / `ToggleLayer3DCommand` в **«Show 2D» / «Show 3D»**
(id команд не менять, тесты `editor-tab.spec.ts` подправить): это фильтры размерности, а не слои, и слово
«слой» не должно значить в редакторе две разные вещи. Отдельно в фазе 1 оно не должно значить и третью.

## Границы фазы 0 (осознанно не делаем)

- Никакого нового свойства узла, таблицы слоёв, YAML-поля и миграции — это фаза 1 и она заморожена.
- Никакой связи с порядком отрисовки, cull-масками камеры, физическими слоями и raycast-фильтрами:
  в Unity/Godot/Cocos переиспользование одного индекса под рендер+физику+рейкасты — главный генератор
  «почему мой объект не рендерится» (плюс канонический баг `layerMask = 8` вместо `1 << 8`).
- Никакого `startsHidden` (это игровое состояние — фаза 1; сегодня выражается `visible: false` на родителе).
- Никакого рантайм-API для скриптов (`scene.layers.hide`) — в фазе 0 канал ровно один, редакторский.
- Никаких хоткеев без модификатора; solo — только модификатор + клик (Blender откатывал это пять
  мажорных версий).
- Никакого шаринга маски в collab: она пер-юзерская. Взамен — `hiddenByEditor` в выводах агента, чтобы
  скриншот агента и картинка пользователя расходились предсказуемо, а не молча.

## Приёмка

Автоматическая:
1. при активной маске вывод `SceneSaver` **байт-в-байт** равен выводу без маски (главный инвариант фичи);
2. `properties.visible` не меняется от маски; запись `node.visible = false` из скрипта по-прежнему пишет
   `properties.visible` (регрессия реактивного слоя);
3. `isVisibleInTree()` для узла под маской — `false`; узел не пикается и не получает ввод;
4. `hiddenByEditor` не переживает serialize→parse (нет в YAML), маска на клон подаётся снаружи и
   восстанавливается после рестарта;
5. экспорт: собранный playable не содержит следов маски (существующие спеки билда + один явный тест);
6. `peek` как инструмент агента: `solo` + `show_all` возвращают набор к исходному.

Ручная (в Flow, живьём):
7. три перекрывающихся UI-экрана: ⌥-клик по чипу гасит остальные, повторный ⌥-клик возвращает **прежний**
   набор, пилюля показывает счётчик и «Show all» работает;
8. маска переживает рестарт стейджа после хода агента и перезагрузку страницы;
9. Download HTML показывает предупреждение про скрытые у вас ветки;
10. скрытый HUD не перехватывает тапы, мир под ним кликается.

## Риски

- **Аксессор `visible` — самый горячий контракт движка.** Минимизируется тем, что механизм один, и спеками
  на реактивный слой и на `SceneSaver`. Если аксессор окажется проблемным (потребитель вроде DeepCore
  компилирует наши исходники своим tsconfig), фолбэк — ставить `hiddenByEditor` через тот же
  `installReactiveSchemaProperties`-подход per-instance.
- **Расхождение картинок в collab и у агента** — принятая цена пер-юзерской маски; лечится только
  видимостью состояния (пилюля + поля в выводах агента).
- **«Скрыл и забыл» перед выдачей** — лечится предупреждением на Export/Download HTML.
- **Автовыведенные чипы могут не совпасть с тем, как человек думает о сцене** — это и есть встроенный
  критерий разморозки фазы 1: если набор нужных групп систематически отличается от верхнеуровневого
  разбиения дерева, значит нужна таксономия.
